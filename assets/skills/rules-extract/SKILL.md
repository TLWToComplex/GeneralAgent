# rules-extract 制度文件摘要工具

自动对制度文件进行结构化总结，把一份可能几十页的制度压缩成一页表格：**七个维度、长度稳定、样式统一**，可快速翻阅，也可下载 Word 文档用于汇报、存档。

## 七个提取维度（每一步都不能跳过）

| 维度 | 说明 | 无信息时 |
|---|---|---|
| 制度名称 | 文件正式名称：发文主体 + 名称 + 文号（如"所财〔2026〕229号"）+ 印发日期 + 施行表述（"自印发之日起执行"），原文有的都要保留，不超过 110 字 | 未知 |
| 核心目标 | 目的句（"为……""旨在……"）+ 制定依据（"依据……制定"）+ 原则句（"坚持/遵循……原则"）+ 适用范围（"适用于……"），1-4 句、合计不超过 200 字 | 未明确提取 |
| 责任主体 | 承担主要责任、执行、监督、管理职责的部门/岗位/人员；每条为"名称：职责"（职责取自原文、尽量完整），不超过 10 条 | 未明确提取 |
| 关键执行步骤 | 具体操作步骤、管理流程、执行要求；每条 = 小标题（≤12 字）+ 内容（≤300 字，保留原文条款的原则、范围、时限、审批层级等细节） | 未明确提取 |
| 关键阈值 | 数量、比例、时限、金额、次数、频率（按日/按月/每周等）等量化标准；每条 = 主题 + "数值+单位+适用语境"（如"总担保规模不得超过合并净资产的40%"） | 未明确提取 |
| 禁止事项 | 原文中"严禁/不得/禁止…"的行为或情形；同一句含多个禁令动词时**逐项拆成独立条目**，每条一个禁令 | 未明确提取 |
| 关键词 | 恰好 10 个（可配）2-8 字专业词语或名词短语（如"资金归集""银行账户管理"），不用动词、不用句子 | 未明确提取 |

## 工作流程

1. **读取输入**：本地文件（`.txt` / `.md` / `.docx` / `.pdf`）、网页 URL 或直接传入的文本。
2. **执行提取**：运行 `scripts/extract_rules.py`（本目录下）。已配置大模型时优先用大模型按七维度结构化抽取；未配置时自动回退本地规则提取。
3. **格式化输出**：默认输出 Markdown 表格；`--output word` 时把同一份内容保存为样式规范的 Word 文档。

## 输出稳定性规则（解决"时长时短"的关键）

- **条数配额**（脚本对大模型结果同样强制执行）：
  | 档位 | 执行步骤 | 关键阈值 | 禁止事项 |
  |---|---|---|---|
  | short | ≤3 条 | ≤5 条 | ≤3 条 |
  | medium | ≤8 条 | ≤12 条 | ≤10 条 |
  | long | ≤16 条 | ≤20 条 | ≤14 条 |
- **字数上限**：制度名称 ≤110 字（发文主体/名称/文号/印发日期/施行表述，原文有的都保留）；核心目标 ≤4 句（目的 + 制定依据 + 原则 + 适用范围）；步骤小标题 ≤12 字、内容 ≤300 字（保留原文条款细节，不过度压缩）；阈值条目带适用语境；责任主体逐条写"名称：职责"（≤10 条）。
- **只引用原文**：所有内容必须能在原文中找到出处，不得扩写、推测、编造数字。
- **合并去重**：意思相同的条目合并为一条，同一数字不重复提取两次。
- **缺失标注**：某维度原文确实没有信息时，填"未明确提取"，不能跳过该维度。
- **关键词纪律**：只收名词性词汇（2-8 字），数量等于 `--keywords-count`（默认 10），不足时按原文高频词补足。
- **禁令拆分**：一句里出现多个"严禁/不得/禁止"时逐项拆成独立条目（脚本自动按分号/动词边界拆分）。

## 输出格式规范

### Markdown 表格（默认）

固定 2 列、7 行结构，逐字参照（列表维度每条一行，用 `<br>` 分隔；除维度列加粗外不做其他装饰）：

```markdown
## 制度摘要

| 信息类别 | 内容 |
|----------|------|
| **制度名称** | 资金管理基本制度（所财〔2026〕229号） |
| **核心目标** | 进一步加强和规范资金管理工作；坚持安全性、效益性、合规性、协同性原则 |
| **责任主体** | 1. 财务资产部：资金归口管理部门，负责组织执行、统筹管理、指导和监控各业务单元资金管理<br>2. 下属公司：本单位资金归口管理部门，主要履行以下职责…… |
| **关键执行步骤** | 1. 银行账户管理：遵循"审慎开立、范围限定、分级监管、主体负责"原则，严控账户数量……<br>2. 资金集中归集：通过财务公司直联银行自动归集，可归集资金原则上全部按日归集…… |
| **关键阈值** | 1. 总担保规模：不得超过合并净资产的 40%<br>2. 单户担保额：不得超过本单位净资产的 50%<br>3. 资金计划上报时限：每月底前 |
| **禁止事项** | 1. 禁止开立功能同质化的账户，禁止不必要的多头开户、重复开户。<br>2. 不得自行或变相搭建其他资金集中平台。 |
| **关键词** | 资金管理、银行账户、资金归集、资金计划、融资担保、票据池、司库管理、责任追究 |
```

### Word 文档（`--output word`）

脚本生成规范、优雅的 `.docx`，样式要点：

- **页面**：A4，上下边距 2.2cm、左右边距 2.4cm。
- **标题区**：主标题"《制度名称》要点摘要"黑体 18pt 加粗、深蓝 `#1F4E79`、居中；下方副题行展示制度全名（发文主体/文号/日期，10.5pt）。
- **说明段**：9pt 灰色居中，形如"说明：本摘要依据原文件全文整理，共6章27条（总则、职责和分工、资金管理重点、资金风险管理、监督考核与责任追究、附则），由 rules-extract 自动生成，供快速查阅，具体执行以原文为准。若集团公司、财务公司新发布制度、规定和流程与本制度相关内容不符的，按照集团公司、财务公司的最新要求执行。"（章节/条款数、章节名、衔接条款均自动提取）
- **表格**：两列固定宽度 4.2cm / 12.0cm，整表居中，长内容自动换行不撑爆单元格。
- **表头**：深蓝 `#1F4E79` 填充、白色加粗黑体 10.5pt、居中。
- **维度列**：浅蓝 `#F2F7FC` 底纹、黑体 10.5pt 深蓝加粗、水平垂直居中。
- **内容列**：宋体 10.5pt 左对齐、1.25 倍行距；每条条目独立成段，条目前的小标题部分加粗显示。
- **隔行着色**：内容列隔行淡蓝 `#EDF3FA` 底纹，便于逐行阅读。
- **边框**：外框 1pt 灰蓝 `#8496B0`，内线 0.5pt `#C9D4E0`。

## 使用方法

```bash
rules-extract --file ./制度文件.md                     # Markdown 表格（默认）
rules-extract --file ./制度文件.md --output word --output-file ./制度摘要.docx   # Word 文档
rules-extract --file ./制度.pdf --output json          # JSON 结果
rules-extract --file ./制度.docx --length long         # 详细档
rules-extract --url https://example.com/rule-page      # 网页抓取并摘要
rules-extract --text "第一章 总则 第一条 为规范……"      # 直接输入文本
```

| 参数 | 说明 | 默认值 |
|---|---|---|
| `--file` / `--url` / `--text` | 输入来源，三选一（必选） | - |
| `--length` | 摘要长度：short / medium / long | medium |
| `--output` | 输出格式：text / markdown / json / word | markdown |
| `--output-file` | Word 输出路径（可选，默认保存到输入文件同目录 `<文件名>_摘要.docx`） | - |
| `--keywords-count` | 关键词数量（5-12） | 10 |
| `--use-llm` | 强制使用大模型提取（需配置 API） | 否 |

## 大模型配置（可选）

通过环境变量 `RULES_EXTRACT_API_KEY` / `RULES_EXTRACT_BASE_URL` / `RULES_EXTRACT_MODEL`，或在用户主目录 `~/.rules-extract/config.json` 配置：

```json
{ "api_key": "your-key", "base_url": "https://api.openai.com/v1", "model": "gpt-4o" }
```

未配置大模型时自动回退本地规则提取，保证开箱可用。

## 输出前自查清单

- [ ] 七个维度一个不少；原文无信息的维度填"未明确提取"
- [ ] 条数与字数符合所选长度档位的配额（见稳定性规则）
- [ ] 内容全部出自原文，数字未改动
- [ ] Markdown 表格与规范模板结构逐字一致
- [ ] Word 文档（如输出）符合样式要点：深蓝标题、表头配色、隔行着色、边框、字号
