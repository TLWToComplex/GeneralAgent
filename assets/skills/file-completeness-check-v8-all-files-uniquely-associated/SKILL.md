# 文件齐套性核查 Skill（LLM 匹配版）

## 用户使用方式

用户只需上传：

- 1 份包含"文件齐套性要求"的文件 —— **支持 DOCX / XLSX / 文本型 PDF**；
- 1 个项目资料 ZIP（包内什么格式都可以，DOCX/XLSX/PDF 会自动附内容摘要）。

然后自然语言提出需求，例如：

- "帮我检查这些文件是否齐套，并生成核查记录。"
- "按要求文档核对项目资料包，告诉我还缺什么。"

**不得要求用户提供文件路径、命令、脚本参数或技能名称。**

### 输入格式与阶段（stage）的对应关系

| 要求文件格式 | 表格取自 | `stage` 取自 |
|---|---|---|
| `.docx` | 正文中的表格 | 表格上方的"××阶段文件齐套性要求"段落 |
| `.xlsx` | 每个 sheet（一 sheet 一段要求） | **sheet 名** |
| `.pdf`（文本型） | pdfplumber 解析出的表格 | 表格上方最近的"××阶段…"标题行 |

三种格式抽出的 `(stage, name)` 必须一致——这是本技能的一致性约束，改动解析逻辑后用 `eval/run_eval_b.py` 验证。

**格式按文件头（magic bytes）判定，不看后缀**：把 `要求.xlsx` 改名成 `要求.pdf` 仍会按 Excel 处理。

## 内部执行规则

### 第一步：数据提取

执行脚本提取要求条目和文件清单：

```bash
python scripts/check_completeness.py \
  --mode extract \
  --requirements "<自动识别的要求DOCX路径>" \
  --project "<自动识别的项目ZIP路径>"
```

脚本输出 JSON 到 stdout，包含：

- `requirements`: 要求条目列表，每个条目含 `stage`（阶段）、`table_index`、`sequence`（序号）、`name`（文件名称）、`remark`（备注）
- `inventory`: ZIP 文件清单，每个文件含 `path`、`stem`（无后缀名）、`suffix`、`preview`（内容摘要，最长 240 字符）

### 第二步：LLM 逐个文件匹配

对 ZIP 中的每个文件，由大模型逐个判断其应归属到哪个要求条目。

**匹配规则：**

1. **"一文件一项"原则**：每个真实文件必须唯一关联到一个要求条目，不得出现在两个条目中
2. 已读到的 `preview` 字段是内容摘要（DOCX 取标题/首段；XLSX 取 sheet 名 + 表头 + 前几行；PDF 取前 2 页文本），可用于辅助判断文件实际内容
3. 将文件与所有要求条目逐一比对，选择语义最匹配的条目

**判定标准：**

| 情况 | 判定 | 说明 |
|------|------|------|
| 文件名与要求名称完全一致或核心语义一致，文件类型（报告/大纲/计划/规范/说明书等）匹配 | `已匹配` | 计入 `files` |
| 要求为集合性质（如"全套图样"、"软件文档"、"通用质量特性工作计划"等），文件覆盖了其中部分子项 | `已匹配` 或 `部分满足` | 将覆盖的子项写入 `covered`，缺失的写入 `missing` |
| 文件主题与要求接近，但名称不完全等同或文件类型不一致（如"策划书"接近"研制方案"、"测试报告"接近"测试计划"） | `疑似匹配` | 计入 `review_files`，不计入 `files` |
| 要求带有"陆军产品"、"空军产品"、"装发方向"、"适用"、"可选"等条件性标记，且无匹配文件 | `待确认适用性` | — |
| 无任何文件能匹配该要求 | `未找到` | — |

**特别注意：**
- 不把"试验报告"当"试验大纲"、"测试报告"当"测试计划"、"产品规范"当"研制规范"——这些是不同类型的文件
- 文件名中带"策划书"的文件，不能直接替代"研制方案/设计方案"，应标记为待人工确认
- "软件测试报告"、"软件测试说明"与"软件文档"要求中的"软件测试计划"不是同一类文件，应标记为待人工确认
- 集合要求中括号内带"如"的（如"通用质量特性设计报告（如：可靠性设计报告等）"），属于示例性列举，有一个或多个相关文件即可判定为"已匹配"，不把未出现的示例项直接判缺

### 第三步：输出匹配结果（TSV 格式）

将第二步的匹配结果直接写入一个 TSV 文件（**不要写 Python 代码来生成，直接输出文本**）。

格式：每行一个要求条目，按 extract 输出的顺序一一对应，Tab 分隔，共 7 列：

```
序号	状态	正式文件	待确认文件	依据	已覆盖	缺失
1	已匹配	项目文件/xxx.docx	-	匹配依据	-	-
2	部分满足	项目文件/a.docx;;项目文件/b.docx	-	说明	子项1;;子项2	子项3
3	未找到	-	-	说明	-	-
4	疑似匹配	-	项目文件/yyy.docx（原因说明）	说明	-	-
```

**列说明：**

| 列 | 含义 | 格式 |
|----|------|------|
| 序号 | 从 1 开始 | 整数 |
| 状态 | 已匹配 / 部分满足 / 疑似匹配 / 未找到 / 待确认适用性 | 固定取值 |
| 正式文件 | 正式齐套依据的文件路径，多个用`;;`分隔 | 无文件填 `-` |
| 待确认文件 | 待人工确认的文件路径，多个用`;;`分隔；需说明原因时格式为 `路径（原因）` | 无文件填 `-` |
| 依据 | 匹配/未匹配的简要说明 | 一句话 |
| 已覆盖 | 集合要求中已覆盖的子项，用`;;`分隔 | 非集合要求填 `-` |
| 缺失 | 集合要求中缺失的子项，用`;;`分隔 | 非集合要求填 `-` |

**示例（前几行）：**

```
1	部分满足	项目文件/差分导航设备研制合同.docx	-	已提供研制合同；缺少研制总要求、技术协议、总体技术要求	研制合同	研制总要求、技术协议、总体技术要求
2	未找到	-	-	研制合同已唯一分配至总体文件条目	-	-
3	已匹配	项目文件/差分导航设备设计方案.docx	项目文件/差分导航设备策划书.docx（策划书不等于设计方案，不能自动替代）	设计方案完全匹配；策划书待确认	-	-
```

**约束：**
- 行数必须与要求条目数一致
- 每个 ZIP 文件必须在"正式文件"或"待确认文件"列中出现且仅出现一次
- 不要输出 JSON、不要写 Python 脚本生成，直接输出 TSV 文本

### 第四步：生成 Word 报告

```bash
python scripts/check_completeness.py \
  --mode generate \
  --requirements "<要求DOCX路径>" \
  --project "<项目ZIP路径>" \
  --matches "<第三步生成的TSV路径>" \
  --output "<平台结果目录>/文件齐套性核查记录.docx"
```

脚本会校验所有文件是否被唯一分配，然后生成 Word 文档。

> **要求文件是 XLSX / PDF 时**：脚本会先按解析出的条目合成一份结构等价的 DOCX 模板（阶段段落 + `序号|文件名称|备注` 表格），在其上标注"备注"列并追加报告；报告里"要求文件"一栏仍显示用户上传的原始文件名。合成的临时文件在 `tempfile` 目录中，用完即删。

## 不支持的情况（要如实告知用户，不要硬试）

| 情况 | 表现 | 处置 |
|---|---|---|
| 扫描件/图片型 PDF（无文本层） | 报错"PDF 无文本层（疑似扫描件）" | 请用户提供 DOCX/XLSX 版要求清单，或先 OCR；**本技能不内置 OCR** |
| `.doc` / `.wps` 旧格式 | 识别为未知格式 | 请用户另存为 `.docx` / `.xlsx` |
| 加密 / 受保护文档 | 解析失败 | 请用户解除保护后重传 |
| 要求文件里没有"文件名称"列 | 报错"未提取到含「文件名称」列的要求表格" | 请用户确认表头命名，或改用模板格式 |

**资源上限**（脚本内置，超出会跳过或报错）：ZIP 成员数 ≤ 20000；单个成员 ≤ 64MB；预览读取 ≤ 8MB。

## 唯一输出文件

仅输出：`文件齐套性核查记录.docx`。

文档包含：

### 第一部分：原要求表核查结果

- 完整保留原要求文件的标题、阶段、序号、文件名称和备注；
- 在"备注"栏标记：
  - `√` 已匹配；
  - `△` 部分满足；
  - `?` 待人工确认；
  - `×` 未找到。

### 第二部分：核查报告说明

按固定顺序输出：

1. 核查结论；
2. 核查范围、标记与统计；
3. **文件对应明细（要求文件 ↔ 实际文件）**：先"方案阶段"，后"样机研制及性能验证试验阶段"；阶段内严格按原表序号排列；每一项写清"要求文件 → ZIP 内真实文件名 → 核查结果"。待人工确认文件必须直接写在其唯一归属的要求项下，前缀标注"待确认："；
4. 需补齐文件：保留"未找到"与"部分满足"项，并写清已上传的真实文件、待确认文件和仍缺内容；
5. 需人工确认文件：写清每一个待确认文件为什么被唯一关联到该要求项、为什么暂不计入齐套、人工需要核对什么；
6. 核查说明。

默认不输出 ZIP 全量文件清单、相似度分数、内部路径、JSON、Markdown 或日志。用户明确要求"详细版"时，仍应将详细内容写入同一个 Word 文档，不得额外生成文件。
