# 文件齐套性核查 Skill（LLM 匹配版）

## 输入

用户上传：

1. `文件齐套性要求.docx` / `.xlsx` / `.pdf`（文本型，三种格式等价）
2. `项目文件.zip`

用户只需要说：

> 帮我检查这些文件是否齐套，并生成核查记录。

要求文件格式不同，`stage`（阶段）的来源也不同：DOCX 取表格上方的阶段段落，XLSX 取 **sheet 名**，PDF 取表格上方的标题行。三者必须抽出一致的 `(stage, name)` 序列。

## 输出

技能只生成并交付 **1 个文件**：

```text
文件齐套性核查记录.docx
```

不会生成：JSON、Markdown 摘要、ZIP 文件清单、临时解压文件夹或调试日志。

## 架构

```
┌─────────────────────────────────────────────────────┐
│  Python 阶段 1：数据提取 (--mode extract)             │
│  - 解析要求文件（DOCX/XLSX/PDF）→ 要求条目列表（JSON） │
│  - 解析 ZIP → 文件清单 + 内容预览（JSON）              │
│    （DOCX/XLSX/PDF 均生成 preview）                   │
│  - 输出到 stdout                                     │
└──────────────────────┬──────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────────┐
│  LLM 阶段：逐个文件判断归属                            │
│  - 读取 requirements 和 inventory                    │
│  - 对每个 ZIP 文件，判断应归属到哪个要求条目            │
│  - 标记是"已匹配"还是"待人工确认"                      │
│  - 直接输出 TSV 文本（不写 Python 代码）               │
└──────────────────────┬──────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────────┐
│  Python 阶段 2：报告生成 (--mode generate)            │
│  - 解析 TSV 匹配结果                                  │
│  - 校验"一文件一项"完整性                             │
│  - 原 DOCX 表格备注栏标注                             │
│  - 追加核查报告章节                                   │
│  - 输出最终《文件齐套性核查记录.docx》                  │
└─────────────────────────────────────────────────────┘
```

## 全量唯一关联规则

每个项目 ZIP 内的真实文件都必须有且只有一个去向：**唯一关联到一个要求条目**。

- 直接符合名称、文件类型和语义的，作为该条目的正式齐套依据；
- 不能直接满足要求、但主题相近的，分配到最接近的条目，显示为 `待确认：文件名`，并在"需人工确认文件"中说明原因；
- 待确认文件**不计入齐套**，但它已经有唯一归属，不能再出现在其他要求项下；
- 不会因为没有足够关键词而把文件遗漏在报告之外。

## 匹配结果格式（TSV）

LLM 直接输出 TSV 文本（不写任何代码），每行一个要求条目，Tab 分隔，7 列：

```
序号	状态	正式文件	待确认文件	依据	已覆盖	缺失
```

| 列 | 说明 | 示例 |
|----|------|------|
| 序号 | 从 1 开始 | `1` |
| 状态 | 已匹配/部分满足/疑似匹配/未找到/待确认适用性 | `已匹配` |
| 正式文件 | 路径用`;;`分隔，无则填`-` | `项目文件/a.docx;;项目文件/b.docx` |
| 待确认文件 | 路径用`;;`分隔，需说明原因时格式为`路径（原因）`，无则填`-` | `项目文件/c.docx（策划书不等于方案）` |
| 依据 | 一句话说明 | `设计方案完全匹配` |
| 已覆盖 | 集合要求的已覆盖子项，`;;`分隔，非集合填`-` | `研制合同` |
| 缺失 | 集合要求的缺失子项，`;;`分隔，非集合填`-` | `技术协议;;总体技术要求` |

**约束：**
- 行数 = 要求条目数
- 每个 ZIP 文件必须且仅出现一次（在正式文件或待确认文件列中）
- 直接输出文本，不要写 Python 代码生成

## Skill 包内文件与核查结果的区别

Skill 解压后看到的 `SKILL.md` 和 `scripts/check_completeness.py` 是技能自身的运行文件，不是核查结果。实际执行结束后，平台结果区只应返回一份 `文件齐套性核查记录.docx`。
